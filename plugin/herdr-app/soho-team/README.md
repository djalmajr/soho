# SoHo panel for Herdr.app

A Herdr.app mod that shows the SoHo team of the project in the shown space. Team groups roles by lane (Build, Review, Risky code, Docs, and any other lane by name), or lists them flat with clickable sorting by role, mode, effort, assistant and model. Mode is text only in this version. Each role has an effort chooser that writes `lane.<lane>.effort` for a lane role and `role.<role>.effort` otherwise; a lane edit changes the whole lane. A row is its Edit target: clicking anywhere on a role row, in Grouped or List, opens the Edit form for that role, and clicking a lane header opens it for the lane; the effort chooser keeps its own click, and hovering only highlights the row. The Edit form sets assistant, model and effort for a lane or one role, previews the exact commands and saves to the project or user config. Every write runs as one literal operand, `soho config set <key>=<value> --project|--user`, so a model id with spaces or a leading dash cannot become a flag or move the destination; the preview shows the same operand with POSIX single quotes where a value needs them. A save uses one validated snapshot of the commands, the previous values and the destination, and waits while a preview for a changed draft is still running. A save shows an inline notice with Undo for eight seconds. View and sort are kept per project folder in the mod's `localStorage`, and a folder change restores that folder's pair. A pending edit, confirmation, Undo plan or cleanup confirm belongs to the space, machine and folder it was opened in and is discarded when that context changes.

Now lists live workers with status, task and elapsed time, and opens a terminal, the parsed report, or a confirmation before closing or reopening a worker. When the installed `soho` refuses `roster --json` because the panel runs outside a Herdr terminal, Now says `This soho cannot list workers from the panel yet.` in the secondary text color instead of an error, and the counter tiles stay hidden until roster answers; the max tile appears only when a positive maximum is known. Report shows partial items and failing test layers first. Assistants shows installed and probed assistants and their roles; Health shows doctor warnings, copies, orphan processes and what gc would remove, with a list of the selected candidates and an inline confirm before cleanup. Health is in the tab bar only when the version reports `health_json`, and a selected tab that loses its capability falls back to Team. The tabs keep the same height, padding and font in every state, so selecting one changes only its background and text color. A missing capability is never an error: the red box is reserved for a command that failed unexpectedly or returned bad JSON. An empty project shows `soho init` as text; the panel never runs init. Widths up to 320 px use a two-line narrow layout with a More menu, in Grouped and in List, 321–559 px use the normal layout, and 560 px and above use a list beside the detail (the worker's report in Now, the Edit form in Team).

## Requirements

The mod needs Go-only `soho` on the machine of the shown space. It reads `soho capabilities --json`, `soho roles --json` and `soho roster --json` on open, every 15 seconds while the panel is visible, after every action and when the folder changes. Polling stops while the copy is hidden: the installed API exposes no visibility call, so the panel polls only when it rendered or reported a non-zero size in the last 30 seconds. Older soho versions still work: without `team_json` the panel groups by `roles[].lane`; without `config_dry_run` it composes the same config commands locally; without `config_unset` Undo appears only for a value already in a config file; without `roster_workers` it uses the base roster fields, including the legacy `state`; without `report_json` it reads the report file in the panel; without `assistants_json` it reads `soho kinds` and `soho models <kind>`; without `health_json` the Health view says that the version cannot report health. Missing keys never fail the whole panel, and a malformed capability answer falls back to that default while the independent reads still run.

Feature keys checked in `soho capabilities --json`: `team_json`, `config_dry_run`, `config_unset`, `roster_workers`, `report_json`, `assistants_json`, `health_json`. With `assistants_json` the Edit form offers only assistants whose probe status is `ready`; when none qualifies it says so and offers Probe again, which runs `soho setup --probe` and reloads. Without `assistants_json` the Edit form lists installed assistants from `soho kinds`. State-changing actions are `soho config set`, `soho config unset`, `soho release <agent> --close`, `soho reopen <agent>`, `soho gc --yes` and `soho setup --probe`; each runs only after a user action, and closing/reopening/cleanup ask for confirmation first.

## Install

Copy the whole folder to `~/.config/herdr-app/mods/soho-team/`, then open the mod from a panel or layout as `soho-team`. Keep `main.js`, `model.js`, `ui.js`, `views.js`, `mod.json`, `icon.svg` and `README.md` together. `tests/model.test.mjs` and `tests/findings.test.mjs` run outside Herdr with `node --test plugin/herdr-app/soho-team/tests/` and import only `model.js`, which has no gpui-kit or herdr dependency.
