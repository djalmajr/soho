# Feature map per transport

This page lists every command the soho CLI dispatches and what each does on the two worker transports: the legacy Herdr TUI (`transport=herdr`, the default) and native Herdr Core (`transport=hc`).

It describes the committed Go code, not the plan. Where the code does not settle a behavior, the cell says `unknown`. Each table row ends with an HTML comment that cites `file:line` for every claim in the row.

The transport is the configuration key `transport`; the environment variable `SOHO_TRANSPORT` wins over the files, and any value other than `hc` counts as `herdr` (`internal/core/config.go:422-433` `TransportMode`). `cli.Run` writes the resolved value back to `SOHO_TRANSPORT` before any backend is built (`internal/cli/cli.go:697-707` `transportModeFor`).

## Glossary

| Noun | Definition |
|---|---|
| orchestrator | The calling agent. It spawns one CLI agent per role, dispatches briefs, collects reports and owns integration, gates and git (`skills/soho/SKILL.md:3-8`). |
| worker | A CLI agent that `soho spawn` starts for one role, recorded as one row of the roster (`internal/core/state.go:20` `rosterHeader`). |
| role | A markdown file with frontmatter (`roles/<role>.md`, overridable per project in `.agents/soho-roles/<role>.md`) that gives a worker its instructions (`internal/cli/usage.go:3` `usage`). |
| lane | A named capacity group that workers are named after (`build`, `review`, `docs`); `lanes=on` is the default (`skills/soho/config.defaults:108`, `skills/soho/SKILL.md:102`). |
| model list | `lane.<name>.models=m1,m2` is an ordered comma list that wins over `lane.<name>.model`; at spawn the first model below `model_cap` is used, counted from every live roster row of the state root (`internal/core/lanes.go:1198-1213` `LaneModels`, `internal/core/lanes.go:1253-1302` `LiveModelCounts`, `internal/spawn/spawn.go:515-557` `ChooseSpawnModel`). | model cap | `model_cap=<n>|off` (default `off`) bounds live workers per model; a full list refuses with exit 13, an explicit `--model` warns and spawns it, and the spawn JSON records `model_choice` (`internal/core/lanes.go:1184-1196` `ModelCap`, `internal/spawn/spawn.go:515-557` `ChooseSpawnModel`, `internal/spawn/spawn.go:1488-1492` `cmdSpawnPrepared`, `internal/spawn/spawn.go:2141` `cmdSpawnPrepared`, `internal/spawn/spawn.go:884` `emitReuse`, `internal/cli/usage.go:3` `usage`). |
| kind | The CLI agent a worker runs: `claude`, `codex`, `grok`, `agy`, `gemini`, `cursor`, `pi`, `opencode` (`internal/kinds/kinds.go:11` `KnownKinds`). |

| report | The file a worker writes when it finishes. Without an assignment, a worker is done when its report exists (`internal/cli/usage.go:3` `usage`, "Completion contract"). |
| roster | `agents.tsv` in the state directory: one tab-separated row per worker with name, pane, kind, role, family, created_pane, cwd, started, model, approvals, roles and lane (`internal/core/state.go:20` `rosterHeader`). |
| state directory | `<state root>/<workspace id>`; the state root defaults to `.soho` (`skills/soho/config.defaults:299`). It holds `briefs/`, `reports/`, `wait/` and the roster (`internal/core/state.go:268-272` `StateDir`). |
| terminal | The unit of `hc`: a persistent program with an address such as `t7` (`skills/soho/references/herdr-ui.md:13`). In the transport contracts it is "one registered agent" (`internal/transport/contracts.go:148` `Terminal`). |
| pane / panel | A split of a Herdr TUI tab that hosts one agent; its id comes from `HERDR_PANE_ID` (`internal/herdr/backend.go:188-195` `Caller`). The skill says "panel" when it talks to the user about a pane (`skills/soho/SKILL.md:71-76`). On hc the pane id field carries the terminal address (`internal/hcbackend/backend.go:624-627` `Caller`). |
| tab | A Herdr TUI tab holding panes. A herd tab is the overflow tab labelled by `herd_label` (`skills/soho/config.defaults:74-84`). The hc backend has no tabs (`internal/hcbackend/backend.go:1123-1125` `ListTabs`). |
| space | The top-level grouping of native `herdr-app`: `spaces[].tabs[].terminals[]` (`skills/soho/references/herdr-ui.md:25`). The soho transport contracts have no space operation (`internal/transport/contracts.go:413-443` `Transport`, `internal/transport/contracts.go:449-479` `Window`). |
| parent | On hc, the terminal that spawned a worker, sent as `caller` and required to be non-empty (`internal/hc/terminal_run.go:319` `Client.RunTerminal`, `internal/hc/terminal_run.go:402` `validateTerminalRun`). The herdr start request has no parent field (`internal/transport/contracts.go:252-286` `Start`). |
| session | The id that names the state directory. On hc it is the `soho.session` label of the caller's terminal, or `hc-<address>` without the label (`internal/hcbackend/backend.go:115-118` `Session`). On herdr it is `HERDR_WORKSPACE_ID` (`internal/herdr/backend.go:188-195` `Caller`). |
| transport | The backend that runs workers: `herdr` (`internal/herdr`) or `hc` (`internal/hcbackend`), chosen by `internal/backend/backend.go:23-28` `New`. |

## Command table

The table covers the commands in `knownCommands` (`internal/cli/cli.go:35-47` `knownCommands`), with a separate row for a subcommand where shown. Status on `hc` is one of `same` (the command path has no transport branch and no backend difference that changes what the user sees), `differs` (a transport branch or a backend method that is a no-op or unsupported on hc changes the result; the hc cell says how), `refused` (the entry guard stops the command; the hc cell quotes the message) or `no-op` (no row has this status; the no-op calls are listed under "Known gaps on the native transport").

Refused commands print `soho: <command> does not support transport=hc yet; set transport=herdr or see DJA-604` on stderr and exit 2. The guard text is `internal/cli/cli.go:392` `Run`. The exact `<command> --help` or `-h` (one flag after a known command, outside `SOHO_NOWRITE`) prints that command's lines before the guard, refused commands included (`internal/cli/cli.go:249-254` `Run`); any longer form of a refused command is refused at the guard.
